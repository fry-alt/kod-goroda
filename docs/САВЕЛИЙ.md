## 3. Сигналы по оценкам (к 11:00 — первая версия)

Константы (названия — дословно колонки xlsx, они уже есть в `make_mock.py`):
`I_SC` — 7 оценок стажёра, `M_SC` — 6 оценок наставника, `I_TX` / `M_TX` — текстовые поля.

**Пары для расхождений.** Список из CLAUDE.md, плюс **предлагаю добавить пятую**:
`«Комфортность нагрузки» ↔ «Соблюдение сроков и организация работы»`. Именно на ней виден случай СТ-004.

Каждый сигнал выглядит так:
`{"id", "level": "red|yellow", "title", "why", "evidence": [{"source", "period", "field", "value", "quote"?}]}`.
**Без `evidence` сигнал не выдаём:** судьи прямо требуют показать, на чём основан вывод.

| Сигнал | Правило (стартовое) | Уровень |
|---|---|---|
| Низкая оценка | любая оценка ≤ 2 в текущем периоде | red |
| Падение к личной норме | норма = среднее этой метрики у человека **за все прошлые периоды**; текущее ниже нормы на ≥ 1 | yellow; на ≥ 2 — red |
| Падение по нескольким | падение ≥ 1 по 2+ метрикам сразу | red |
| Расхождение пары | \|стажёр − наставник\| ≥ 2 в текущем периоде | yellow; держится 2 из 3 последних периодов — red |
| Пропуск опроса | нет анкеты стажёра или наставника в текущем периоде | yellow (red — если пропуск 2 периода подряд) |
| Риск в комментарии | ИИ пометил `risk=true` (см. п. 4) | yellow; подтверждён оценкой ≤ 2 или вторым источником — red |
| Повторяющаяся проблема | одна и та же тема-проблема в комментариях 2+ периода подряд | yellow |
| Подтверждено двумя сторонами | одну тему называют и стажёр, и наставник в одном периоде | повысить уровень на ступень |

В **Месяц 1** личной нормы ещё нет, поэтому там работают только абсолютные правила (≤ 2, пары, комментарии).

**Светофор стажёра в периоде:** есть red-сигнал → `red`; есть yellow → `yellow`; иначе `green`.
`reason` в overview — `title` самого серьёзного сигнала.
Пороги вынеси в константы в начале файла, чтобы их можно было быстро подкрутить.

## 4. ИИ-разметка комментариев (к 11:30)

Используй готовый слой `feedback/analyzers/llm.py`: провайдер YandexGPT → Claude → офлайн, ответ по JSON-схеме, кеш.
Сделай новую pydantic-схему, например:

```python
class CommentAnalysis(BaseModel):
    topics: list[str]   # из списка ниже
    tone: str           # "позитив" | "нейтрально" | "негатив"
    risk: bool          # есть проблема, на которую HR стоит отреагировать
    quote: str          # дословная короткая цитата-основание
```

Темы (поправь `feedback/taxonomy.py` под них): **понятность задач**, **обратная связь / поддержка наставника**,
**нагрузка**, **самостоятельность**, **сроки и планирование**, **команда**, **развитие**, **интерес к задачам**.

Размечаем по периоду: 2 комментария стажёра и 2 комментария наставника. Кеш по хешу текста. Офлайн-словарь — запасной вариант.

**Ловушки в данных (проверь руками, это потом пойдёт в тесты):**
- «Нагрузка **вернулась к комфортному** уровню», «Сложностей за период **не было**», «Ничего не мешает»,
  «Критичных сложностей **нет**» → `risk=false`. Отрицания!
- СТ-004, Месяц 4: «Нагрузка была **слишком высокой**…» → `risk=true`, тема «нагрузка».
  **Сейчас мок это пропускает** (`comment_analysis.risk=false`), офлайн-словарь надо расширить.
- СТ-002, Месяц 4: «Иногда нагрузка выше комфортной» — максимум жёлтый, не красный.
- СТ-005, Месяцы 1–3: «не хватает обратной связи / быстро задать вопрос / регулярных встреч» →
  повторяющаяся проблема **3 периода подряд**.

> ⚠️ **Поправка к CLAUDE.md.** Там написано, что по СТ-004 «наставник перегрузку не видит». В оценках
> это так (сроки 4), но в тексте наставник **видит**: «из-за нагрузки часть сроков пришлось перенести»,

## 5. Резюме и действия для HR (к 11:50)

На стажёра в периоде: `summary` (2–3 предложения) и `actions` (1–3 конкретных действия).
На вход LLM подаём **только посчитанные факты**: сигналы с `evidence` и цитаты. Сырые таблицы модели не даём,
чтобы она не выдумывала цифры.

Офлайн-шаблон по типу сигнала:
- нагрузка → «пересмотреть загрузку с наставником»;
- обратная связь → «ввести регулярные короткие встречи стажёр–наставник»;
- расхождение → «встреча втроём HR–стажёр–наставник»;
- пропуск → «напомнить заполнить анкету».

В данных это ровно то, что помогло СТ-003 и СТ-005.

Резюме кешируем по хешу входа, тогда новый ответ пересчитывает только одного стажёра.
